# 端到端融合跟踪算法软件：交付清单与范围

对应合作开发协议成果清单第 3 项“端到端融合跟踪算法软件，软件，包括 Matlab 和 C 语言，1 份”。本次按 **1 套算法软件**整理，包含完整 Web 前后端、MATLAB/C 推理入口、Python 预处理与训练程序。MATLAB 与 C 共用固定尺寸 V7 ONNX 模型和 ONNX Runtime 推理核心。

## 二、脚本的交付边界

“脚本”只是文件形式，不能单凭扩展名判断是否属于软件。`run_tracker.m` 是 MATLAB 的实际运行入口；`verify_golden_case.m` 和 `verify_delivery.ps1` 是验收验证工具；C 源文件、头文件和构建配置也属于可交付软件。它们应随软件包保留。

工程与软件包统一使用训练入口 `train.py`。2026-10-12 已删除工程原有的 MAT 训练入口，并将实际用于配准 PKL 训练的 `train_cv.py` 更名为 `train.py`；后续制包直接复制根目录 `train.py`。现有 ZIP 中的训练程序内容与此次更名前的 `train_cv.py` 一致。MAT→PKL 配准程序及依赖、ONNX 导出和核验程序均纳入软件包。`tracking_system/` 的前端、后端和后端测试完整纳入；`results/` 整目录纳入，没有只挑选个别权重。`scripts/evaluation/` 随后端纳入；数据生成、绘图和制包工具不纳入。原始 V5～V8 `.mat` 数据已另行打包。

ZIP 内最外层目录统一命名为 `end_to_end_tracking_software/`；内部保留 `tracking_system/frontend/` 与 `tracking_system/backend/`。`tracking_system` 是后端 Python 包名，代码中的导入和启动命令依赖这个名称，因此不单独改成 `app` 等新名称。前端依赖由 `package.json` 和 `package-lock.json` 声明，交付包不放机器生成的 `node_modules`。

主要目录如下：

```text
end_to_end_tracking_software/
├─ tracking_system/frontend/   # 完整前端源码与依赖锁文件
├─ tracking_system/backend/    # 完整后端源码与测试
├─ src/                        # 算法与数据解析模块
├─ scripts/                    # 预处理与后端评估程序
├─ portable/                   # MATLAB/C 推理入口与运行库
├─ results/                    # 84 个历史结果文件，整目录纳入
├─ artifacts/metrics/          # Web 历史指标数据
└─ artifacts/reports/batch_tests/ # Web 批测历史状态
```

## 三、功能、接口和限制

| 项目 | 当前实现 |
|---|---|
| 部署环境 | Windows x64；MATLAB MEX 由 R2026a 编译；C 版本使用 ONNX Runtime 1.18.1 |
| 输入条件 | 已完成目标关联、时间对齐和空间配准的单目标序列；18 个连续 `float32` 输入张量 |
| 固定尺寸 | 批量 1；每条序列 100 帧；协同平台 5 个 |
| 输出 | `[1,100,6]`，状态顺序 `[px,vx,py,vy,pz,vz]`；位置为 ECEF 绝对坐标，速度单位 m/s |
| 调用入口 | MATLAB：`run_tracker.m`；C：`tracker_create` / `tracker_run` / `tracker_destroy` |
| 输入详表 | 包外 `portable/INTERFACE.md`（与第 4 项配套文档一同移交） |

包内 Python 预处理程序可将原始 `.mat` 转成完成关联与配准的 `.pkl`，唯一训练程序读取配准 PKL。**MATLAB/C 推理入口仍接收 18 个已组织好的张量**，不直接读取原始 `.mat` 或 `.pkl`；Web 后端可加载配准 PKL 并提供推理及批测接口。V8 原始样例为 400 帧，不能直接送入固定 100 帧的 MATLAB/C 接口；需先按接口要求处理。该边界应在软件演示和验收时说明。

- C 黄金样例在当前工作区执行通过：最大位置差 0.5 m，最大速度分量差约 0.0472 m/s。
- 从本次软件 ZIP 解包复测：V7 原始验证场景 `track_ca_0000.mat` 成功配准成 PKL；唯一训练入口的命令行可加载；导出程序直接使用包内 `src` 和 V7 权重生成 ONNX，位置最大差约 0.5154 m、速度分量最大差约 0.1014 m/s，均在现有跨语言一致性门槛内；C 黄金样例通过。原有正式模型文件未被覆盖。
- MATLAB 黄金样例本轮未能重新执行：默认预设文件夹不可写；改用工作区预设目录后，MATLAB 启动报 MathWorks 服务通信错误 5201。包内保留 MEX、测试向量和验证脚本，供具备可用 MATLAB 授权环境时复核。
- 项目已有 V7 完整验证集评估记录，报告状态为 `passed`；该记录与本轮是否能启动 MATLAB 是两项不同的验证。Web 接口读取的指标 JSON 随 `artifacts/metrics/` 纳入包内；正式测试报告及第 4 项文档仍在包外单独整理。
- 从完整软件包解压运行后端测试，19 项全部通过。前端离线安装尝试因本机 npm 缓存缺少 `zrender` 包而停止，未完成本轮构建验证；前端源码、静态资源、配置和锁文件均已核对在包内，联网安装依赖后可按下文命令构建。

软件包另附逐文件 SHA-256 清单和整个 ZIP 的 SHA-256 文件，便于移交后核对。协议附图规定成果形式和数量；本文件的具体实现范围依据当前工程文件与运行验证整理。

## 五、解包后使用

将 ZIP 解压到英文路径，保持 `end_to_end_tracking_software/` 下的目录层级；现有 C 验证程序的命令行路径转换尚未覆盖中文路径。MATLAB 调用时将 `portable/matlab` 加入路径，再以 `run_tracker(modelPath, input)` 传入符合包外 `portable/INTERFACE.md` 的输入结构；C 集成时引用 `portable/c/include/tracker.h`，链接 `portable/c/build/Release/coop_tracker.lib`，并确保 `onnxruntime.dll` 位于可加载路径。

从交付包根目录运行 `portable/verify_delivery.ps1` 可先执行 C 黄金样例，再尝试 MATLAB 黄金样例。MATLAB 需在本机具备可用安装与授权；C 重新编译需 CMake、C 编译器以及包内 ONNX Runtime 头文件和库文件。

Web 后端从交付包根目录运行 `python -m tracking_system.backend.server`；前端进入 `tracking_system/frontend` 后执行 `npm ci`、`npm run build` 或 `npm run dev`。前端构建依赖不随源码包复制；后端默认需要 `data/val_data_v7_registered/`，该目录需从独立原始数据包完成预处理后生成。首次缺少配准数据时，先按下方命令运行预处理再启动后端。

Python 预处理、训练与导出命令应在 `end_to_end_tracking_software` 目录运行，环境版本见包外 `docs/software_delivery/Python环境依赖.txt`。下面以 V7 为例；原始数据来自单独交付的数据包，输出 PKL 和新训练结果由运行时生成。

```powershell
python scripts/pipelines/run_register_pipeline.py --in_dir data/train_data_v7 --out_dir data/train_data_v7_registered
python scripts/pipelines/run_register_pipeline.py --in_dir data/val_data_v7 --out_dir data/val_data_v7_registered
python train.py --data_dir data/train_data_v7_registered --val_data_dir data/val_data_v7_registered --epochs 40 --batch_size 32
python portable/python/export_onnx.py --model results/runs_40off(v7)/run_20260728_103728/best_model.pt --data-dir data/val_data_v7_registered --seq-len 100 --num-uavs 5 --output-dir portable/artifacts
```

包内唯一的 `train.py` 使用配准 PKL 训练。导出命令示例指定的是包内原有 V7 权重；若重新训练，应把 `--model` 改为新生成的 `best_model.pt`。重新导出会覆盖 ONNX 和黄金样例，需重新执行跨语言验证后方可替换已验收模型。
